# 项目实践：遇到的问题与解法

> 面向「智守」智能 OnCall Agent。下文按真实踩坑整理：先说问题，再说怎么打通、为什么这样设计。

## 1. 如何把后端与运维 Agent 打通

这是整条链路的骨架：**前端只打 HTTP，真正排障的是 Spring AI 编排出来的 Agent**。

### 1.1 卡在哪

早期容易把「对话接口」做成「调一次 LLM 把文本返回」。这样无法：

- 自动查 Prometheus 告警、CLS 日志、内部知识库
- 多步规划（先看告警 → 再查日志 → 再对照手册）
- 把同一套工具同时给「问答 Agent」和「告警分析 Agent」用

后端和 Agent 之间缺一层：**谁创建 Agent、谁注入工具、谁把结果流回前端**。

### 1.2 打通方式：三层接线

```
前端 (index.html / app.js)
        │  HTTP / SSE
        ▼
ChatController
  /api/chat、/api/chat_stream     → 问答 ReactAgent
  /api/ai_ops                    → Supervisor + Planner + Executor
        │
        ▼
ChatService / AiOpsService
  ① ChatModelFactory 按 provider 建模型
  ② 召回经验 + 滚动摘要 → system prompt
  ③ methodTools（Java @Tool）+ tools（MCP ToolCallback）注入 Agent
        │
        ▼
工具层
  本地：queryPrometheusAlerts / queryInternalDocs / loadSkill / saveMemory …
  MCP：ConvertTimeStringToTimestamp → TextToSearchLogQuery → SearchLog …
  数据：Prometheus、Milvus、MySQL、腾讯云 CLS
```

要点有三条：

**入口统一在 Controller。**  
问答走 `POST /api/chat`（整包返回）和 `POST /api/chat_stream`（SSE）。告警分析走 `POST /api/ai_ops`（无需用户输入，超时放宽到 10 分钟）。前端不直接碰模型或 MCP。

**Agent 由后端现场组装，而不是常驻进程。**  
`ChatService.createReactAgent` 把系统提示词、本地方法工具、MCP 回调绑到同一个 `ReactAgent` 上：

```java
ReactAgent.builder()
    .name("intelligent_assistant")
    .model(chatModel)
    .systemPrompt(systemPrompt)
    .methodTools(buildMethodToolsArray())   // Java @Tool
    .tools(getToolCallbacks())              // Spring AI MCP 客户端拉到的工具
    .build();
```

AIOps 再往上包一层 `SupervisorAgent`：Planner 拆步骤，Executor 只执行当前第一步，Supervisor 在 PLAN / EXECUTE / FINISH 之间调度，直到输出《告警分析报告》。

**工具分两类，职责分开。**

| 来源 | 代表能力 | 说明 |
|------|----------|------|
| 本地 `@Tool` Bean | 时间、Prometheus、知识库、Skill、记忆 | 始终注入 |
| MCP `ToolCallbackProvider` | 腾讯云 CLS 全套查询 | 始终注入 |

日志查询走 CLS MCP，告警查询走 Prometheus。

### 1.3 一次问答实际怎么走

1. Controller 解析 `sessionId`，从 MySQL 取最近窗口历史  
2. `ExperienceService.recallForPrompt` 召回相关排障经验  
3. `ConversationSummaryService` 取出滑出窗口的滚动摘要  
4. 拼 system prompt（指令 + 经验 + 摘要），历史改成原生 `UserMessage` / `AssistantMessage`  
5. `agent.call(messages)` 或 `agent.stream(messages)`：模型自行决定调哪些工具  
6. 回答落盘后异步做三件事：经验提炼、摘要滚动、情景记忆归档  

告警分析路径类似，只是入口换成 Supervisor，经验查询用固定的运维症状词，报告成功/失败再回写经验评分。

## 2. Windows 上 CLS MCP 连不上

### 问题

Spring AI MCP 客户端用 **stdio JSON-RPC** 拉起 `cls-mcp-server`。该包启动时会往 **stdout** 打一行普通文本（如 `Started cls-mcp-server...`）。协议要求 stdout 只能是 JSON 行，握手立刻失败，Agent 侧表现为「没有日志工具」。

Windows 上还有第二层坑：`npx.cmd` 必须走 `shell: true`，路径还依赖本机 Node（`C:/nvm4w/nodejs`）。

### 解法

加一层 `scripts/cls-mcp-stdio-wrapper.cjs`：

- 用 `npx -y cls-mcp-server@latest` 拉起 CLS MCP
- **只把合法 JSON-RPC 行转发到 stdout**
- 启动横幅、日志打到 stderr，不污染协议流

`application.yml` 里 MCP 的 `command` 指向 `node.exe` + 该包装脚本，密钥走环境变量。本地开发另备 `mcp-servers.json` 方便手工调试，运行时以 Spring 配置为准。

## 3. 模型乱调 CLS、或直接编造日志

### 问题

CLS 查询不是单次 `SearchLog`：要先换时间戳、可选查 TopicId、自然语言转 CQL，再检索，必要时拉上下文。Region 必须是 `ap-chengdu` 这种连字符格式。把整本手册塞进每轮 system prompt 会浪费 token；不写手册，模型就会跳步、填错 Region、甚至编几条「看起来像」的 ERROR。

### 解法：程序性知识做成 Skill，按需加载

- 手册放在 `classpath:skills/cls-log-query/SKILL.md`  
- `AgentSkillService` 启动扫描；加载 `cls-log-query` 时再附上当前环境的 TopicId 对照表  
- 暴露 `listSkills` / `loadSkill` 两个工具  
- system prompt 只留一句：**查 CLS 前必须 `loadSkill(name=cls-log-query)`，禁止凭记忆编顺序或编日志**  
- Planner / Executor / Supervisor 提示词同样强制这条  

空结果也写进 Skill：近窗口 0 条是正常现象，可放大到 1 小时再查；仍空就如实说，不要假装查到了。同一工具连续失败 3 次必须停手。

## 4. 对话记不住：重启丢失、窗口外消失、跨会话失忆

### 问题

最初历史放在 Controller 的 `ConcurrentHashMap` 里，最多 6 轮，进程重启即空。后来改成 MySQL 后，又把历史**拼成纯文本塞进 system prompt**：角色边界糊、token 浪费；滑出窗口的内容虽然在库里，Agent 永远看不见。用户问「上次 pay-service OOM 怎么处理的」答不上。

### 解法：工作记忆 / 摘要 / 情景记忆拆开

| 层 | 实现 | 解决什么 |
|----|------|----------|
| 工作记忆 | MySQL `chat_message` + 原生多轮 `messages` | 重启不丢；角色清晰 |
| 滚动摘要 | 滑出窗口的旧轮次由 LLM 压成摘要注入 system prompt | 长对话不丢早期背景 |
| 情景记忆 | 每轮问答向量化进 Milvus，工具 `searchPastConversations` | 跨会话回忆 |
| 语义记忆 | 经验库（见下一节） | 可复用的排障因果，而不只是聊天原文 |

对话结束后这三件事都**异步**做，失败不影响主响应。

## 5. 经验「存了用不上」，同类故障还是从零排

### 问题

- 弱经验进 `experience_temp` 后没有任何召回路径，等于死存储  
- 召回只看「相似度 × 置信度」，上周刚处理的故障和一年前的权重一样  
- 只能新增不能合并，同一根因刷出一堆近似条目  
- 用户说「记住这个结论」时 Agent 没有写入工具  
- AIOps 失败不会给经验打负分，无效经验置信度只升不降  

### 解法

1. **弱经验与强经验同进 Milvus**，`tier=weak`、置信度打折；评分爬升后晋升 `strong`；长期不用再衰减归档。  
2. **L3 评分加 recency**：`finalScore = 相似度 × 置信度 × recency`，半衰期 14 天、下限 0.3。  
3. **高相似（≥0.85）走合并更新**，而不是再插一条。  
4. 增加 `saveMemory` / `searchMemory`，允许 Agent 主动记、主动搜。  
5. AIOps **成功**给本次召回经验加分并沉淀报告；**流程失败/无报告**批量减分；**基础设施异常不评分**，避免误伤。  

注入提示词时写明：经验只作参考方向，必须结合当前工具证据验证，禁止直接照搬执行。

## 6. AIOps 跑完了，前端却没有报告

### 问题

Planner 在执行阶段被要求输出 JSON（`decision: PLAN|EXECUTE|FINISH`），FINISH 时又被要求改输出 Markdown 报告。模型经常继续吐 JSON，或把报告塞进 `finalReport` 字段。提取逻辑最初只读 `planner_plan` 一个 key，格式稍偏就整份报告丢失，后面的经验沉淀、评分也全部跳过。

### 解法

提示词把 FINISH 约定写死：**不要 JSON，从 `# 告警分析报告` 起输出固定模板**。提取做成三级链：

1. `planner_plan` 已是 Markdown → 直接用  
2. 仍是 JSON → 抽 `finalReport` / `report` / `content`  
3. 扫描整个编排状态，优先含「告警分析报告」的文本，否则取最长的实质性输出  

Supervisor 还规定：同一方向工具连续失败 3 次必须终止，输出「无法完成」及原因，禁止编造。

## 7. 知识库：格式少、召回不准

### 问题

早期只按纯文本切 `.txt` / `.md`。PDF、Word 上传后无法入库。向量检索 Top-3 太狠：真正有用的「磁盘清理步骤」可能排在第 5，根本进不了上下文。

### 解法

- **提取层与分片层解耦**：按扩展名走 MD / TXT / PDF / Word Processor，再套对应 ChunkStrategy（Markdown 按标题，PDF 按页等）。  
- **两阶段检索**：Milvus 先粗召回 10 条，再用 `qwen3-rerank` 精排，只把 Top-3 交给模型。  
- 启动可对 `aiops-docs/` **增量入库**，已向量化的文件不重复切。  

问答时知识库不是「每次把整库塞进 prompt」，而是 Agent 按需调用 `queryInternalDocs`。

## 8. 双模型切换把 Spring AI 自动装配打乱

### 问题

对话希望可选 DeepSeek 或通义千问，经验提炼固定 DeepSeek，Embedding / Rerank 仍走 DashScope。若让 Starter 自动注册全局 `ChatModel`，两个供应商会抢同一个 Bean，请求级切换做不到。

另外，告警分析、工具循环耗时长，默认 HTTP 超时容易在中途断掉。

### 解法

```yaml
spring.ai.model.chat: none    # 禁止自动注册全局 ChatModel
```

`ChatModelFactory` 按请求的 `provider` 现场创建 `OpenAiChatModel`（DeepSeek 兼容协议）或 `DashScopeChatModel`。DeepSeek 通过 `extraBody.thinking` 区分思考/非思考。`DashScopeConfig` 把 RestClient 超时拉到 180 秒，给工具循环留余量。

## 9. 前后端契约错位（小坑，但会直接 413 / 会话分叉）

| 现象 | 原因 | 处理 |
|------|------|------|
| 前端能选 `.markdown`，后端 400 | 白名单只有 `md` | `allowed-extensions` 补上 `markdown` |
| 大于 1MB 的文档 413 | Spring Boot 默认 multipart 1MB，前端限制 50MB | 两边都改成 50MB |
| 新会话刷新后接不上 | 后端生成了 sessionId，响应没回传；前端删会话只清 localStorage | `/api/chat` 和 SSE done 帧带回 sessionId；删除时同步 `POST /api/chat/clear` |

这些不是 Agent 能力问题，但会让「功能做好了、页面上却像坏了」。

## 可以对外讲的设计原则

1. **HTTP 是门面，Agent 是执行器**：Controller 只负责会话、SSE 和组装；推理、工具选择交给 ReactAgent / Supervisor。  
2. **本地工具与 MCP 工具并列注入、职责分开**：知识库、Skill、记忆走 Java `@Tool`；日志走 CLS MCP，告警走 Prometheus。  
3. **长流程不进 system prompt**：用 Skill 按需 `loadSkill`，降低 token、提高遵从度。  
4. **记忆分层**：窗口内原文、窗口外摘要、跨会话情景、可复用经验，各管各的。  
5. **经验必须可验证、可打分**：召回只作假设，工具证据说了算；成功加分、失败减分、基础设施故障不罚。  
6. **模型输出不可信，提取要有兜底**：尤其是多 Agent 的 JSON/Markdown 混用场景。
